# 项目进度管理 · 重点知识点

> 第4版教材第10章 · 6 个过程 · 综合知识 4~6 分 · **案例分析必考计算（关键路径、时差）**

---

## 一、定位：进度是"三约束"里最硬的

**核心定义**：进度管理是管理项目**按时完成**所需的所有过程。

**进度管理的两个核心产出**

| 产出 | 内容 |
|---|---|
| **进度基准** | 经过批准的进度模型，含基准开始/完成日期（只有"制定进度计划"产出） |
| **项目进度计划** | 具体的活动、时间、资源安排（可以是横道图、里程碑图、网络图） |

**6 个过程与过程组分布**

```
规划 ─── 规划进度管理、定义活动、排列活动顺序、估算活动持续时间、制定进度计划
监控 ─── 控制进度
```

**逻辑链**：**定规则 → 拆活动 → 排顺序 → 估工期 → 排进度 → 控进度**

**三条容易记错的点**
1. "定义活动"是**进度管理**的过程，不是范围管理；活动来自对**工作包**的分解
2. "制定进度计划"才输出**进度基准**，前面几个过程都没有
3. "控制进度"输出的是**进度预测**，不是进度基准

### 10.3 定义活动

**关键理解**：WBS 分解到**工作包**，再把工作包分解为**活动**（进度管理的最小单元）。

- **活动清单**：项目所需的全部活动，附活动标识与工作描述
- **活动属性**：活动标识、WBS 标识、活动名称、活动编码、逻辑关系、提前量与滞后量、资源需求、强制日期、制约因素、假设条件
- **里程碑清单**：里程碑是**重要的时点或事件**，**持续时间为零**，不消耗资源

**工具辨析**

| 工具 | 说明 |
|---|---|
| **分解** | 把工作包分解为活动 |
| **滚动式规划** | 近期活动详细规划，远期活动粗略规划，随进展细化 |

---

### 10.4 排列活动顺序

**PDM（紧前关系绘图法）/ 单代号网络图**

四种逻辑关系（必背）

| 关系 | 缩写 | 含义 |
|---|---|---|
| **完成到开始** | **FS** | A 完成后 B 才能开始（**最常用**） |
| **完成到完成** | FF | A 完成后 B 才能完成 |
| **开始到开始** | SS | A 开始后 B 才能开始 |
| **开始到完成** | SF | A 开始后 B 才能完成（**很少用**） |

**依赖关系分类**

| 类型 | 说明 | 能否调整 |
|---|---|---|
| **强制依赖**（硬逻辑） | 合同或工作性质决定，如"先浇筑后养护" | **不可调整** |
| **选择性依赖**（软逻辑） | 基于最佳实践，如"先做两个模块再集成" | **可调整**（赶工时的突破口） |
| **外部依赖** | 项目与外部之间，如"等政府审批" | 通常不可控 |
| **内部依赖** | 项目内部活动之间 | 可调整 |

**提前量（Lead）与滞后量（Lag）**
- **提前量**：后置活动可以**提前**开始的时间（如 FS−5 天）
- **滞后量**：后置活动必须**延后**开始的时间（如 FS+5 天，等待养护）

**项目进度网络图**：展示活动之间的逻辑关系，**不展示时间**（区别于横道图）。

---

### 10.5 估算活动持续时间（计算高频）

**四种估算法对比**

| 方法 | 原理 | 准确度 | 适用 |
|---|---|---|---|
| **类比估算** | 参考**类似历史项目** | 低 | 早期、信息少、快速 |
| **参数估算** | 用**参数模型**（如每平方米工时 × 面积） | 中高 | 有历史数据、可量化 |
| **自下而上估算** | 逐层汇总**最底层**估算 | **最高** | 详细、成本高 |
| **三点估算** | 考虑**不确定性**（PERT） | 中高 | 有风险、不确定性大 |

**三点估算公式（必背）**

```
三角分布（简单平均）：
  TE = (O + M + P) / 3

贝塔分布（PERT 加权，考试默认用这个）：
  TE = (O + 4M + P) / 6
  σ  = (P − O) / 6

方差 = σ²
```

> O=最乐观，M=最可能，P=最悲观。**没说是哪个分布时，一律用 PERT 贝塔分布 /6。**

**储备分析**
- **应急储备（Contingency Reserve）**：应对**已识别**风险，包含在**进度基准**内，由 PM 管理
- **管理储备（Management Reserve）**：应对**未识别**风险，**不包含**在进度基准内，由**高层**管理

### 10.6 制定进度计划（案例必考）

**关键路径法（CPM）—— 案例第一题的核心**

**定义**：网络图中**最长的路径**，决定项目**最短工期**。

| 概念 | 公式 |
|---|---|
| **总时差 TF** | TF = LS − ES = LF − EF |
| **自由时差 FF** | FF = min(紧后活动 ES) − 本活动 EF |
| **关键路径** | **总时差 = 0** 的活动组成的路径 |
| **关键活动** | 关键路径上的活动，**没有机动时间**，任何延误都会推迟工期 |

**正推法（求 ES/EF）**

```
ES = max(所有紧前活动的 EF)      （起始活动 ES = 0）
EF = ES + 持续时间
```

**逆推法（求 LS/LF）**

```
LF = min(所有紧后活动的 LS)      （末尾活动 LF = 项目工期）
LS = LF − 持续时间
```

**例题模板**

```
活动  紧前  工期
A     -     3
B     A     4
C     A     2
D     B,C   5

正推：A: ES=0,EF=3  B: ES=3,EF=7  C: ES=3,EF=5  D: ES=max(7,5)=7,EF=12
项目工期 = 12
逆推：D: LF=12,LS=7  B: LF=7,LS=3  C: LF=7,LS=5  A: LF=min(3,5)=3,LS=0
总时差：A=0 B=0 C=LF-EF=7-5=2 D=0
关键路径：A→B→D（总时差为 0）
```

**关键路径的三个性质（易错）**
1. 关键路径**可能有多条**
2. 关键路径是**最长**路径，不是最短
3. 关键路径上活动延误，项目**一定**延误；非关键活动在**总时差范围内**延误，项目**不**延误

**资源优化**

| 方法 | 做法 | 对工期的影响 |
|---|---|---|
| **资源平衡（Resource Leveling）** | 让资源需求**平滑**，可能改变关键路径 | **通常会延长**工期 |
| **资源平滑（Resource Smoothing）** | 在**总时差内**调整活动，不动关键路径 | **不延长**工期 |

> 口诀：**平衡可能延期，平滑绝不延期。**

**进度压缩（案例常考）**

| 方法 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **赶工（Crashing）** | 增加资源、加班 | **增加成本** | 关键路径上的活动 |
| **快速跟进（Fast Tracking）** | 并行开展原本串行的工作 | **增加风险、可能返工** | 可并行的活动 |

> 只能压缩**关键路径**上的活动，压缩非关键活动对工期**无影响**。

**进度计划的表现形式**
- **里程碑图**：只显示关键里程碑与日期（给高层看）
- **横道图（甘特图）**：显示活动与持续时间（最常用）
- **项目进度网络图**：展示活动逻辑关系

### 10.7 控制进度

**关注**：活动状态、进度偏差、进度基准变更。

**工具要点**
- **挣值分析**：SV、SPI 判断进度绩效
- **迭代燃尽图**：敏捷项目用，看剩余工作量趋势
- **假设情景分析**：分析"如果…会怎样"
- **进度压缩**：出现偏差后追赶进度的手段

**对进度偏差的处理**
- 偏差在**总时差内** → 一般不需采取措施
- 偏差**超出总时差** → 影响工期，必须提变更请求

## 四、高频易错对照表

| # | 陷阱 | 正解 |
|---|---|---|
| 1 | 关键路径是最短路径 | 关键路径是**最长**路径，决定最短工期 |
| 2 | 关键路径只有一条 | **可能有多条** |
| 3 | 非关键活动不能延误 | 在**总时差范围内**可以延误 |
| 4 | 资源平滑可以延长工期 | 平滑在总时差内调整，**不延长**；**平衡**才可能延长 |
| 5 | 赶工可用于任何活动 | 只能压缩**关键路径**上的活动 |
| 6 | 快速跟进没有代价 | 增加**风险与返工**可能 |
| 7 | 三点估算一律除以 3 | 默认用 PERT **除以 6**，三角分布才除 3 |
| 8 | 管理储备包含在进度基准内 | **不包含**，由高层管理；应急储备才在基准内 |
| 9 | 里程碑有持续时间 | 里程碑**持续时间为 0**，不消耗资源 |
| 10 | 定义活动属范围管理 | 属**进度管理**，活动来自工作包分解 |
| 11 | 网络图能看出时间安排 | 网络图只表示**逻辑关系**，横道图才表示时间 |
| 12 | 控制进度输出进度基准 | 输出**进度预测** |
| 13 | 提前量是延后 | **提前量是提前**（Lead），滞后量才是延后（Lag） |
| 14 | 总时差等于自由时差 | 总时差≥自由时差，只有关键路径上两者可能为 0 |

## 五、案例题万能模板

**计算题标准作答步骤（必须写过程，跳步扣分）**

```
第一步：画网络图，标注各活动工期
第二步：正推法求 ES、EF
        ES = max(紧前 EF)，起始活动 ES = 0
        EF = ES + 工期
第三步：确定项目工期
        项目工期 = 所有活动 EF 的最大值
第四步：逆推法求 LS、LF
        LF = min(紧后 LS)，末尾活动 LF = 项目工期
        LS = LF − 工期
第五步：计算总时差
        TF = LS − ES = LF − EF
第六步：识别关键路径
        TF = 0 的活动连成的路径即关键路径，可能有多条
第七步：回答结论
        项目最短工期 = X 天，关键路径 = A→B→D
```

**进度延误类案例的常见问题与措施**

```
问题：
1. 未制定可行的进度计划，或计划未获批准即执行
2. 未识别关键路径，资源投入集中在非关键活动
3. 进度偏差未及时发现，未采取纠偏措施
4. 进度变更未走整体变更控制流程
5. 未考虑资源可用性与依赖关系，计划不可行
6. 未设置合理的应急储备

措施：
1. 使用关键路径法制定进度计划，明确关键活动
2. 优先保障关键路径活动的资源
3. 建立进度监控机制（定期绩效审查、挣值分析）
4. 出现偏差时分析原因，采取赶工/快速跟进，并走变更流程
5. 合理设置应急储备与管理储备
6. 使用资源平衡优化资源配置
```
