# 项目干系人管理 · 重点知识点

> 第4版教材第17章 · 4 个过程 · 综合知识 2~3 分 · 案例与论文高频

---

## 一、定位：干系人管理的目标是"参与"，不只是"识别"

**核心定义**：干系人管理是识别影响项目或被项目影响的人员/组织，并**管理他们对项目的期望与参与程度**的过程。

**关键论断**
> 干系人管理的目标不是"让所有人满意"，而是让**关键干系人**在**恰当的时机**、以**恰当的方式**参与项目。**参与（Engagement）比沟通更进一步**——沟通是传递信息，参与是让干系人真正投入。

**4 个过程与过程组分布**

```
启动 ─── 识别干系人
规划 ─── 规划干系人参与
执行 ─── 管理干系人参与
监控 ─── 监督干系人参与
```

> **重要**：第4版把"识别干系人"移到**启动**过程组（第3版在规划），这意味着**项目一开始就要识别干系人**。

---

## 二、四个过程总表

| 过程 | 过程组 | 关键输入 | 关键工具 | 关键输出 |
|---|---|---|---|---|
| **识别干系人** | 启动 | 项目章程、立项管理文件、项目管理计划、项目文件、协议、EEF、OPA | 专家判断、数据收集（**头脑风暴、问卷调查**）、**数据分析（干系人分析、文件分析）**、数据表现（**干系人参与度评估矩阵**）、会议 | **干系人登记册**、变更请求、项目管理计划更新 |
| **规划干系人参与** | 规划 | 项目管理计划、项目文件、协议、EEF、OPA | 专家判断、数据收集、数据分析、**决策**、数据表现（**干系人参与度评估矩阵**）、会议 | **干系人参与计划** |
| **管理干系人参与** | 执行 | 项目管理计划、项目文件、EEF、OPA | 专家判断、**沟通技能、人际关系与团队技能、基本规则**、会议 | **变更请求**、项目管理计划更新、项目文件更新 |
| **监督干系人参与** | 监控 | 项目管理计划、项目文件、工作绩效数据、EEF、OPA | 数据分析、决策、数据表现、沟通技能、人际关系与团队技能、会议 | 工作绩效信息、变更请求 |

**三条容易记错的点**
1. **识别干系人**在**启动**过程组（唯一的启动过程之一，另一个是制定项目章程）
2. **干系人参与度评估矩阵**既在识别干系人（记录现状），也在规划干系人参与（规划目标）中使用
3. **管理干系人参与**是**执行**过程，输出**变更请求**

## 三、逐个重点

### 17.2 识别干系人

**核心**：尽可能**全面**地识别所有干系人，并分析他们的利益、影响、期望。

**干系人分析（Stakeholder Analysis）**

分析三个维度：
| 维度 | 说明 |
|---|---|
| **权力（Power）** | 对项目的影响力大小 |
| **利益（Interest）** | 对项目结果的关心程度 |
| **影响（Influence）** | 能主动影响项目的能力 |

**权力-利益方格（Power/Interest Grid，必考）**

```
            利益低                利益高
权力高  ┌──────────────┬──────────────┐
        │  保持满意     │  重点管理     │
        │  (Keep        │  (Manage      │
        │   Satisfied)  │   Closely)    │
        ├──────────────┼──────────────┤
权力低  │  监督         │  随时告知     │
        │  (Monitor)    │  (Keep        │
        │               │   Informed)   │
        └──────────────┴──────────────┘
```

| 象限 | 策略 |
|---|---|
| **权力高 + 利益高** | **重点管理**（manage closely）——最优先 |
| **权力高 + 利益低** | **保持满意**（keep satisfied）——别让他们阻碍 |
| **权力低 + 利益高** | **随时告知**（keep informed）——他们需要信息 |
| **权力低 + 利益低** | **监督**（monitor）——最低投入 |

**干系人登记册的内容（必背）**
① 姓名/组织/职位
② 角色（在项目中的身份）
③ **主要需求与期望**
④ **对项目的影响（权力）**
⑤ 对项目的态度（支持/中立/反对）
⑥ 联系信息
⑦ 分类（内部/外部、支持/反对）

---

### 17.3 规划干系人参与

**核心**：制定策略，让干系人按需参与。

**干系人参与度评估矩阵（Stakeholder Engagement Assessment Matrix，必考）**

五种参与程度（**C = 当前，D = 期望**）

| 参与程度 | 含义 |
|---|---|
| **不知晓（Unaware）** | 不知道项目及其潜在影响 |
| **抵制（Resistant）** | 知道项目，但**不配合/反对** |
| **中立（Neutral）** | 知道项目，但**既不支持也不反对** |
| **支持（Supportive）** | 知道项目，**支持**并愿意配合 |
| **领导（Leading）** | 知道项目，**积极参与并推动** |

**矩阵示例**

```
干系人          不知晓  抵制  中立  支持  领导
张总（发起人）                  C    D
李经理（客户）        C          D
王工（技术负责人）                  C/D
赵财务            C      D
```

> 目标：**把 C 移动到 D**。如李经理现在是"抵制"，期望"支持"——需要针对性沟通。

**干系人参与计划内容**
- 每个干系人的**期望参与程度**
- 所需的**沟通与互动策略**
- 参与的时间点与频率
- 责任人与资源
- 可能的风险与应对

---

### 17.4 管理干系人参与

**核心**：**执行**参与计划，与干系人沟通协作，满足其需求，处理其关注点。

**关键工具**

| 工具 | 说明 |
|---|---|
| **沟通技能** | 与干系人有效交流 |
| **人际关系与团队技能** | 建立信任、解决冲突、谈判、政治敏锐性 |
| **基本规则（Ground Rules）** | 明确互动规则，减少摩擦 |

**关键论断**
> 管理干系人参与要**主动**（proactive），而不是等干系人有意见了才处理。尤其是**潜在反对者**，要提前沟通化解。

**处理反对干系人的策略**
1. 早期识别（识别干系人阶段）
2. 了解真实诉求（不是表面理由）
3. 寻找共赢点
4. 必要时**上报**高层
5. 保持透明与尊重

---

### 17.5 监督干系人参与

**核心**：监控干系人关系，调整策略以提升参与效果。

**关注点**
- 干系人参与程度是否达到期望（C 是否向 D 移动）
- 干系人满意度
- 是否出现新的干系人或新的关注点
- 沟通是否有效

**输出：工作绩效信息**——关于干系人参与有效性的信息。

## 四、高频易错对照表

| # | 陷阱 | 正解 |
|---|---|---|
| 1 | 识别干系人在规划过程组 | 第4版放在**启动**过程组 |
| 2 | 干系人管理就是沟通管理 | 参与（engagement）比沟通更进一步，**情感投入** |
| 3 | 权力高利益低的要重点管理 | 该象限是**保持满意**；重点管理是权力高**利益也高** |
| 4 | 权力低利益高的可以忽略 | 要**随时告知**，否则他们会变成反对者 |
| 5 | 干系人参与度评估矩阵只有四个等级 | 有**五个**：不知晓、抵制、中立、支持、领导 |
| 6 | 矩阵中的 C 是期望程度 | **C = 当前（Current）**，D = 期望（Desired） |
| 7 | 干系人登记册是 OPA | 属**项目文件** |
| 8 | 干系人越多越好 | 要识别**全部相关方**，但管理精力应按矩阵分级 |
| 9 | 反对者应排除在项目外 | 应**主动沟通、了解诉求、寻找共赢** |
| 10 | 管理干系人参与属监控过程 | 属**执行**过程组 |
| 11 | 干系人参与计划属于项目管理计划 | 属**项目文件**（干系人参与计划） |
| 12 | 只需关注支持者 | 更要关注**潜在反对者**，提前化解 |

## 五、案例题万能模板

```
问题：
1. 未识别全部干系人，遗漏关键干系人（如运维、财务、最终用户）
2. 未做干系人分析，未区分权力与利益
3. 未制定干系人参与计划，参与无策略
4. 未识别潜在反对者，需求评审时被推翻
5. 沟通单向，未了解干系人真实诉求
6. 干系人变更未及时更新登记册
7. 未定期评估干系人参与效果

措施：
1. 用头脑风暴、问卷、文件分析全面识别干系人，形成干系人登记册
2. 用权力-利益方格做干系人分析，分级管理
3. 制定干系人参与计划，明确目标参与程度与策略
4. 主动与潜在反对者沟通，了解诉求并寻找共赢方案
5. 建立双向沟通机制，定期收集反馈
6. 干系人变化时及时更新登记册与参与计划
7. 用参与度评估矩阵定期评估 C 到 D 的移动情况
```

## 六、论文要点（论干系人管理）

**结构**：背景 300 字 → 过程论述 1500 字 → 问题与解决 400 字 → 总结 200 字

**必须体现的加分项**
- **一次真实的干系人冲突**：运维部门一开始"抵制"（担心增加工作量）→ 通过参与需求评审 + 提供培训 → 转为"支持"
- **权力-利益方格的应用**：识别 18 位干系人，4 位"重点管理"、3 位"保持满意"
- **参与度矩阵的量化**：项目初期 5 人"中立"、2 人"抵制"，结束时全部达到"支持"以上
- **上报的时机**：当财务总监始终抵制时，上报发起人协调
