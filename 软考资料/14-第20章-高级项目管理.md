# 第20章 高级项目管理 · 重点知识点

> 第4版教材第20章 · 综合知识 2~3 分 · 案例偶考（项目集、项目组合、PMO）

---

## 一、定位：从"单个项目"上升到"组织级管理"

**三个层级的管理对象（必考辨析）**

| 层级 | 管理对象 | 目标 | 关注点 |
|---|---|---|---|
| **项目组合（Portfolio）** | **一组项目和项目集** | 实现**组织战略目标** | **优先级排序、资源分配**（做不做） |
| **项目集（Program）** | **一组相互关联的项目** | 获得**单独管理无法实现的收益** | **项目间的依赖与协调**（怎么协同） |
| **项目（Project）** | 单个项目 | 交付特定产品/服务/成果 | 范围、进度、成本、质量 |

> **核心区别一句话**：
> - 项目组合 = **为了战略，选对的事**（优先级）
> - 项目集 = **为了收益，让事协同**（依赖关系）
> - 项目 = **为了交付，把事做成**

**关系图示**

```
组织战略
   ↓
项目组合（Portfolio）—— 战略层：选择与优先级
   ↓
项目集（Program）—— 收益层：协调与整合
   ↓
项目（Project）—— 交付层：执行
```

## 二、核心知识

### 20.1 项目组合管理

**定义**：为了实现**战略目标**，对一组项目和项目集进行**集中管理**，包括识别、排序、授权、管理和控制。

**关键特征**
- 组合中的项目**不一定相互依赖**
- 核心动作是**优先级排序**与**资源优化配置**
- 关注**整体投资回报**（ROI）
- 决策依据：战略一致性、风险、收益、资源约束

**项目组合管理的关键活动**
```
① 制定组合战略（与组织战略对齐）
② 识别与评估候选项目
③ 优先级排序（打分/加权评分）
④ 资源分配与平衡
⑤ 监控与调整（定期评审，砍掉低价值项目）
```

> **最重要的一句话**：项目组合管理**可以终止**某个项目，因为它服务于组合整体价值最大化。

### 20.2 项目集管理

**定义**：对**相互关联**的项目进行**协调管理**，以获得分别管理无法实现的**收益**。

**关键特征**
- 项目集内的项目**必须相互依赖**（共享资源、共同目标、有依赖关系）
- 核心是**收益管理**（Benefits Management）
- 关注**项目间的接口与依赖**
- 项目集经理的职责是**协调**，不是直接管项目细节

**项目、项目集、项目组合对比（必背）**

| 维度 | 项目 | 项目集 | 项目组合 |
|---|---|---|---|
| 管理对象 | 单个项目 | 一组**相关**项目 | 一组项目/项目集 |
| 目标 | 交付成果 | 实现**收益** | 实现**战略目标** |
| 核心关注 | 三重约束 | **依赖与协调** | **优先级与资源** |
| 成功标准 | 范围/时间/成本达标 | **收益实现** | **整体投资回报** |
| 管理者 | 项目经理 | 项目集经理 | 项目组合经理 |
| 变更态度 | 尽量抵制变更 | 适应变更以获收益 | 主动调整组合 |

### 20.3 PMO（项目管理办公室）

**三种 PMO 类型（必背）**

| 类型 | 支持程度 | 对项目的控制 | 说明 |
|---|---|---|---|
| **支持型（Supportive）** | 低 | **低** | 提供模板、培训、经验教训库，**顾问角色** |
| **控制型（Controlling）** | 中 | **中** | 提供支持 + **要求项目遵循**特定流程与规范 |
| **指令型（Directive）** | 高 | **高** | **直接管理**项目，项目经理向 PMO 汇报 |

> 记忆：**支持型给工具，控制型给规矩，指令型给命令。**

**PMO 的主要职责**
- 制定项目管理标准与流程
- 提供模板、工具、培训
- 跨项目资源协调
- 项目监控与报告汇总
- 经验教训管理与知识沉淀
- 项目组合/项目集管理的支持

### 20.4 组织级项目管理（OPM）

**定义**：把**项目组合、项目集、项目**管理与**组织驱动因素**（战略、文化、流程）结合，实现组织战略目标的能力框架。

**OPM 的三个层次（易考）**
```
组织级（战略与治理）
  ↓
项目组合级（选择与优先级）
  ↓
项目集/项目级（执行与交付）
```

**关键论断**：**OPM 的核心是"战略—项目"的对齐**，确保做的项目都是在支撑战略。

### 20.5 项目治理

**定义**：为项目提供**指导、监督与控制**的框架与流程。

**治理与管理的区别**

| | 治理（Governance） | 管理（Management） |
|---|---|---|
| 层级 | **高层/董事会** | 执行层 |
| 关注 | **做不做、该不该做**（方向） | **怎么做、做得好不好**（执行） |
| 动作 | 决策、监督、问责 | 计划、组织、控制 |

**关键论断**：**治理是"道"，管理是"术"**。治理决定方向与边界，管理负责落地。

### 20.6 组织文化与项目

**文化对项目的影响（易考）**
- 支持型文化：鼓励沟通、容忍失败、决策快
- 保守型文化：层层审批、规避风险、决策慢

> 关键论断：**组织文化是项目的"隐形环境"**。同样的方法论在不同文化中效果差异巨大。这也是"案例题里项目失败原因"的常见答案之一。

## 三、拓展：敏捷与混合型项目管理

**敏捷宣言四条价值观（必背）**
```
个体和互动     高于  流程和工具
工作的软件     高于  详尽的文档
客户合作       高于  合同谈判
响应变化       高于  遵循计划
```
> 注意：敏捷不是否定右侧，而是**左侧更有价值**。

**Scrum 的三个角色**
- **产品负责人（PO）**：管理产品待办列表（Product Backlog），代表客户价值
- **Scrum Master**：服务型领导，移除障碍，保证流程
- **开发团队**：自组织，跨职能

**Scrum 的五个会议**
```
Sprint 计划会 → 每日站会 → Sprint 评审会 → Sprint 回顾会
（Sprint 本身是 1~4 周的迭代周期）
```

**三个工件**
- 产品待办列表（Product Backlog）
- Sprint 待办列表（Sprint Backlog）
- 增量（Increment）

**看板（Kanban）**
- 可视化工作流（待办/进行中/完成）
- **限制在制品数量（WIP Limit）**——核心机制
- 不要求固定迭代周期，持续流动

**混合型（Hybrid）**
- 组合预测型与适应型：如"总体瀑布规划 + 局部敏捷迭代"
- 适用：大型项目、组织转型期、部分模块需求明确

## 四、高频易错对照表

| # | 陷阱 | 正解 |
|---|---|---|
| 1 | 项目组合内的项目必须相关 | 组合内项目**不一定相关**，靠战略关联 |
| 2 | 项目集就是几个项目放一起 | 项目集必须有**相互依赖关系**与共同收益目标 |
| 3 | 项目组合管理不管战略 | 组合管理**直接服务战略目标** |
| 4 | 项目集经理直接管项目细节 | 项目集经理负责**协调**，不替项目经理管细节 |
| 5 | 三种 PMO 支持程度相同 | 支持型（低）< 控制型（中）< 指令型（高） |
| 6 | 指令型 PMO 只是顾问 | 指令型 PMO **直接管理项目** |
| 7 | 治理就是管理 | 治理管**方向与问责**，管理管**执行与效率** |
| 8 | 敏捷否定文档的价值 | 敏捷认为**工作软件更有价值**，不否定文档 |
| 9 | Scrum Master 是项目经理 | SM 是**服务型领导**，不是传统项目经理 |
| 10 | 看板必须固定迭代周期 | 看板**不要求固定周期**，强调持续流动 |
| 11 | 项目组合成功标准是按时交付 | 组合的成功标准是**整体投资回报/战略实现** |
| 12 | 敏捷不适用于大项目 | 可用**混合型**或规模化敏捷框架 |

## 五、案例题万能模板

```
从组织级管理角度看，问题可能是：
1. 缺乏项目组合管理，项目未按战略优先级排序
2. 项目间依赖关系未识别，资源冲突频繁
3. PMO 定位不清，既当顾问又当管理者
4. 缺少项目治理机制，决策无问责
5. 组织文化不支撑项目（审批冗长、规避风险）

措施：
1. 建立项目组合管理，用加权评分做优先级排序
2. 对相关项目采用项目集管理，明确收益目标与依赖
3. 明确 PMO 类型与职责（支持型/控制型/指令型）
4. 建立项目治理框架，明确决策权限与问责机制
5. 培育支持型组织文化，缩短决策链条
```

## 六、论文要点

**必须体现的加分项**
- **项目集管理的一次实践**：3 个相关项目如何协调，实现单独管理无法获得的收益（如统一数据平台）
- **PMO 的定位**：作为控制型 PMO，为 12 个项目建立统一模板与月度评审
- **治理的作用**：通过治理委员会否决了一个战略不符的项目，避免 200 万投入
- **文化与项目的互动**：如何在保守型组织中推动敏捷实践
