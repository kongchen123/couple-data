# 项目质量管理 · 重点知识点

> 第4版教材第12章 · 3 个过程 · 综合知识 3~4 分 · 案例高频（质量保证与质量控制的混淆）

---

## 一、定位：质量管理的核心是"过程 vs 结果"

**核心定义**：质量管理是把组织的**质量政策**应用于规划、管理、控制项目的质量和产品，以满足干系人期望的过程。

**两个关键概念**

| 概念 | 定义 | 关注 |
|---|---|---|
| **质量（Quality）** | 满足要求的程度 | **符合需求**（conformance to requirements） |
| **等级（Grade）** | 功能多少、技术特性高低 | 功能数量（低等级不等于低质量） |

> 关键论断：**低等级不是问题，低质量才是问题。** 一个低等级但符合需求的产品是可接受的。

**三个过程与过程组分布**

```
规划 ─── 规划质量管理
执行 ─── 管理质量（原"质量保证"）
监控 ─── 控制质量
```

> 第4版把"质量保证"改名为"**管理质量**"，范围扩大为既保证过程、也保证团队质量意识。

**质量管理的逻辑**

```
定标准（规划）→ 保证过程按标准执行（管理质量）→ 检查成果是否达标（控制质量）
```

---

## 二、三个过程总表

| 过程 | 过程组 | 关键输入 | 关键工具 | 关键输出 |
|---|---|---|---|---|
| **规划质量管理** | 规划 | 项目章程、项目管理计划、项目文件、EEF、OPA | 专家判断、数据收集、数据分析、**决策**、**数据表现**、**测试与检查的规划**、会议 | **质量管理计划**、**质量测量指标**、项目管理计划更新 |
| **管理质量** | 执行 | 项目管理计划、项目文件、OPA | **数据收集、数据分析、决策、数据表现、审计、面向 X 的设计、问题解决、质量改进方法** | **质量报告**、测试与评估文件、变更请求 |
| **控制质量** | 监控 | 项目管理计划、项目文件、**批准的变更请求**、可交付成果、工作绩效数据、EEF、OPA | **数据收集、数据分析、检查、测试/产品评估、数据表现、会议** | **质量控制的测量结果**、**核实的可交付成果**、工作绩效信息、变更请求 |

**三条容易记错的点**
1. **管理质量**在**执行**过程组，输出**质量报告**（不是"质量保证"）
2. **控制质量**的输出是"**核实的**可交付成果"，供"确认范围"使用
3. **质量报告**包含质量管理问题、改进建议、纠正措施，是管理质量的核心输出

## 三、逐个重点

### 12.2 规划质量管理

**质量管理计划内容**：质量标准、质量目标、角色与职责、质量评审方式、**质量测量指标**、质量核对单、过程改进方法。

**质量测量指标（举例）**
- 缺陷密度（每千行代码缺陷数）
- 缺陷率、测试覆盖率
- 返工率、准时率
- 客户满意度（NPS）

**两大质量观点（易考）**

| 观点 | 代表人物 | 核心主张 |
|---|---|---|
| **质量是管理者的责任** | **戴明（Deming）** | 85/15 法则：85% 的质量问题源于**管理**和**系统**，只有 15% 源于工人 |
| **零缺陷** | **克劳斯比（Crosby）** | 第一次就把事情做对，**预防**而非检查 |
| **适用性质量** | **朱兰（Juran）** | 质量就是"**适用性**"，提出质量三部曲：质量计划、质量控制、质量改进 |

**数据表现工具（规划阶段）**
- **流程图**：展示过程步骤，识别可能出问题的环节
- **逻辑数据模型**：组织数据的可视化
- **矩阵图**：找因素之间的关系强度
- **思维导图**：梳理质量要求

---

### 12.3 管理质量（原质量保证）

**核心**：关注**过程**是否按标准执行，以及**团队质量意识**。

| 对比 | 管理质量 | 控制质量 |
|---|---|---|
| 关注对象 | **过程** | **成果/产品** |
| 问题性质 | 过程是否有效 | 产品是否合格 |
| 类比 | 检查"做法对不对" | 检查"结果好不好" |
| 主要工具 | **质量审计** | **检查、测试** |
| 输出 | **质量报告** | **核实的可交付成果** |

> 记住：**管理质量 = 过程；控制质量 = 结果。**

**质量审计（核心工具，必背）**

- 定义：**独立的、结构化的审查**，判断项目活动是否遵循组织政策、过程和程序
- 目的：识别**良好实践**与**低效政策**，形成改进建议
- 执行者：**内部审计员**或**外部第三方**（必须**独立于项目团队**）
- 频率：可以**事先安排**，也可以**随机**
- 输出：改进建议 → 变更请求 → 更新过程

**面向 X 的设计（DFX）**
把质量要求前置到设计阶段，如：可制造性、可维护性、可靠性、安全性、可测试性。

**问题解决（Problem Solving）—— 结构化方法**

```
① 定义问题
② 识别根本原因（鱼骨图、5 Whys）
③ 生成可能方案
④ 选择最佳方案
⑤ 实施
⑥ 验证有效性
```

**质量改进方法**
- **PDCA 循环**（戴明环）：计划 → 执行 → 检查 → 处理
- **六西格玛**：DMAIC（定义、测量、分析、改进、控制），追求 3.4 ppm 缺陷率
- **精益**：消除浪费

### 12.4 控制质量

**核心**：检查**可交付成果**是否符合质量标准，输出**核实的可交付成果**。

**七大质量工具（老七工具，必背）**

| 工具 | 用途 | 关键特征 |
|---|---|---|
| **因果图**（鱼骨图/石川图） | 找**根本原因** | 人机料法环测（5M1E） |
| **流程图** | 展示过程步骤，识别问题环节 | 找**哪一步出问题** |
| **核查表** | 系统化收集缺陷数据 | 计数用的表格 |
| **帕累托图** | 找**主要问题** | **二八法则**，先解决占比最大的 |
| **直方图** | 展示数据分布 | 看**分布形态** |
| **控制图** | 判断过程**是否稳定** | **七点规则**：连续 7 点在同一侧 → 过程失控 |
| **散点图** | 找两变量**相关性** | 看是否线性相关 |

**老七工具记忆口诀**
> **因果流程查，帕累直控散**（因果图、流程图、核查表、帕累托、直方图、控制图、散点图）

**其他重要工具**

| 工具 | 说明 |
|---|---|
| **统计抽样** | 从总体中抽样检查，注意**置信水平**与**抽样比例** |
| **检查（Inspection）** | 测量、审查、验证工作产品 |
| **测试/产品评估** | 结构化测试，验证产品是否满足要求 |
| **质量核对单** | 逐项确认质量要求是否达成 |

**控制图的关键概念（易考）**

```
UCL（控制上限）—— 通常 μ + 3σ
  ─────────────
CL（中心线）—— μ
  ─────────────
LCL（控制下限）—— 通常 μ − 3σ

七点规则：连续 7 个点落在中心线同一侧 → 过程失控（即使都在上下限内）
超出控制限：某点超出 UCL/LCL → 过程失控
```

> 重要区分：**控制限 vs 规格限**。控制限由**过程自身波动**决定；规格限由**客户/合同要求**决定。过程可能在统计控制内（稳定）但**不满足规格**（不合格）。

**质量的三个层次（易考）**
- **预防**：防止缺陷产生（最经济）
- **检查**：发现缺陷（成本中等）
- **返工**：修复缺陷（成本最高，还耽误工期）
- **缺陷逃逸到客户**：成本最高（索赔、信誉）

## 四、高频易错对照表

| # | 陷阱 | 正解 |
|---|---|---|
| 1 | 管理质量是监控过程 | 管理质量属于**执行**过程组 |
| 2 | 管理质量关注产品是否合格 | 关注**过程**是否有效；控制质量才管产品 |
| 3 | 质量保证就是管理质量 | 第4版已改名"管理质量"，范围扩大到团队质量意识 |
| 4 | 控制质量输出"验收的可交付成果" | 输出"**核实的**"，确认范围才输出"**验收的**" |
| 5 | 质量审计可以自己做 | 必须**独立于项目团队**（内部审计员或外部机构） |
| 6 | 帕累托图用于看分布 | 用于找**主要问题**（二八法则）；直方图才是看分布 |
| 7 | 控制图超出规格限就是失控 | 控制限看**过程稳定性**，规格限看**是否合格**，两者不同 |
| 8 | 连续 7 点在限内就正常 | 连续 **7 点在同一侧**即判为失控（趋势） |
| 9 | 低等级等于低质量 | 等级低但符合需求，质量没问题 |
| 10 | 戴明主张靠检验保证质量 | 戴明主张 **85% 质量问题源于管理**，反对大规模检验 |
| 11 | 质量成本越高越好 | **预防成本**投入产出最高；外部失败成本最贵 |
| 12 | 管理质量的输出是核实的可交付成果 | 输出**质量报告** |
| 13 | 控制质量可以在管理质量之前做 | 逻辑上是**先管理质量（保证过程）→ 再控制质量（检查结果）** |
| 14 | 缺陷发现得越早成本越高 | **越晚发现成本越高**，所以要预防和早期检查 |

## 五、案例题万能模板

```
问题：
1. 未制定质量管理计划，质量标准不明确
2. 缺乏质量测量指标，无法量化评价
3. 未开展质量审计，过程执行无监督
4. 只做最终检验，未做过程控制（重检查轻预防）
5. 质量数据未用统计工具分析，凭经验判断
6. 发现缺陷后未做根本原因分析，同类问题重复发生
7. 质量与进度冲突时，牺牲质量赶工期

措施：
1. 编制质量管理计划，明确标准、目标、职责与核对单
2. 设定可量化的质量测量指标（缺陷率、返工率、覆盖率）
3. 定期开展质量审计（独立审计员），形成改进建议
4. 建立"预防为主"的质量体系，加强设计评审与过程检查
5. 使用因果图找根本原因、帕累托图抓主要问题、控制图监控稳定性
6. 对不合格品执行缺陷补救流程，并更新经验教训
7. 质量优先于进度，冲突时走变更流程调整基准
```

## 六、论文要点（论质量管理）

**结构**：背景 300 字 → 过程论述 1500 字 → 问题与解决 400 字 → 总结 200 字

**必须体现的加分项**
- **一次真实的质量改进**：上线后缺陷率 8%，通过增加代码评审 + 自动化测试，降到 2.3%
- **质量审计的落地**：每季度 1 次，发现"测试用例未覆盖边界条件"等问题 12 项
- **七工具的实战使用**：用帕累托图发现 80% 缺陷集中在 2 个模块
- **质量成本数据**：预防投入 15 万，减少返工 40 万，净收益 25 万

<summary>答案</summary>

1. 规划 1（规划质量管理）、执行 1（管理质量）、监控 1（控制质量）。

3. 管理质量关注过程（质量审计），输出质量报告；控制质量关注成果（检查/测试），输出核实的可交付成果。

6. 帕累托图按频次降序排列找主要问题（二八法则）；直方图看数据的分布形态。
7. 连续 7 个点落在中心线同一侧 → 判为失控。
8. 控制限由过程自身波动决定（μ±3σ），看稳定性；规格限由客户要求决定，看是否合格。
9. 85% 的质量问题源于管理和系统，只有 15% 源于工人。
