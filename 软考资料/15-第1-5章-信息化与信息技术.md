## 二、第1章 信息化发展

### 1.1 信息的特征（必背）

```
客观性、普遍性、无限性、动态性、相对性、依附性、变换性、传递性、层次性、系统性、转化性
```

> 最常考：**客观性**（信息是客观事物反映）、**依附性**（需载体）、**变换性**（可转换形式）、**传递性**。

### 1.2 信息的质量属性（必背）

| 属性 | 含义 |
|---|---|
| **精确性** | 准确程度 |
| **完整性** | 全面程度 |
| **可靠性** | 可信程度 |
| **及时性** | 时间有效性 |
| **经济性** | 获取成本 |
| **可验证性** | 可被验证 |
| **安全性** | 不被非法访问 |

> 记忆：**精完可及经可安**（精确、完整、可靠、及时、经济、可验证、安全）。

### 1.3 信息化与工业化融合

- **两化融合**：信息化与工业化融合
- 三个层次：**技术融合、业务融合、产业融合**
- **两化深度融合**：从"物理融合"到"化学融合"

### 1.4 国家信息化体系六要素（必背）

```
① 信息技术应用（龙头）
② 信息资源（核心）
③ 信息网络（基础设施）
④ 信息技术和产业（基础）
⑤ 信息化人才（关键）
⑥ 信息化政策法规和标准规范（保障）
```

> 记忆：**应用是龙头，资源是核心，网络是基础，产业是支撑，人才是关键，法规是保障。**

### 1.5 新型基础设施（新基建）三大类

| 类型 | 内容 |
|---|---|
| **信息基础设施** | 通信网络（5G、光纤、卫星）、新技术（AI、云计算、区块链）、算力（数据中心、超算） |
| **融合基础设施** | 智能交通、智慧能源、工业互联网 |
| **创新基础设施** | 重大科技基础设施、科教基础设施、产业技术创新设施 |

### 1.6 数字中国

- **数字经济**：数字产业化、产业数字化
- **数字政府**：一网通办、一网统管
- **数字社会**：智慧城市、数字乡村
- **数字生态**：数据要素市场

**数据要素的四个环节**：**采集、存储、流通、应用**（也有"采集-加工-流通-应用"表述）

### 1.7 数字经济分类（易考）

| 类别 | 含义 |
|---|---|
| **数字产业化** | 信息技术产业本身（电子信息制造、软件、通信） |
| **产业数字化** | 传统产业用数字技术升级（工业互联网、智慧农业） |

**数字经济的三层架构**：**数字产业化、产业数字化、数字化治理**（+ 数据价值化）

### 1.8 元宇宙、区块链等新技术概念

- **元宇宙**：虚拟与现实融合的互联网形态，特征为**沉浸感、开放性、永续性**
- **区块链**：**分布式账本**，特征：去中心化、不可篡改、可追溯、公开透明
- **NFT**：非同质化通证，唯一性、不可分割

## 三、第2章 信息技术发展

### 2.1 物联网（IoT）三层架构（**必考**）

```
感知层（Perception）—— 采集数据
   ↓
网络层（Network）—— 传输数据
   ↓
应用层（Application）—— 处理与应用
```

> 记忆：**感（采集）→ 网（传输）→ 应（处理）**。
> 有时补充"平台层"，但标准三层是**感知、网络、应用**。

**物联网的关键技术**
- 感知层：传感器、RFID、二维码、摄像头
- 网络层：NB-IoT、LoRa、5G、ZigBee
- 应用层：云计算、大数据、AI

### 2.2 云计算（**必考**）

**三种服务模式（必背）**

| 模式 | 全称 | 用户得到什么 | 类比 |
|---|---|---|---|
| **IaaS** | Infrastructure as a Service | 基础设施（服务器、存储、网络） | 租毛坯房 |
| **PaaS** | Platform as a Service | 平台（开发环境、中间件、数据库） | 租装修好的房 |
| **SaaS** | Software as a Service | 软件（直接用应用） | 住酒店 |

> 记忆：从下往上 **I → P → S**，用户管理的东西越来越少。

**四种部署模式**
- **公有云**：第三方提供，多租户共享
- **私有云**：单一组织专用
- **社区云**：特定社区共享
- **混合云**：公有 + 私有组合

**云计算的特征（5 个）**
```
按需自助服务、广泛网络访问、资源池化、快速弹性、可计量服务
```

### 2.3 大数据（**必考**）

**5V 特征（必背）**

| V | 含义 |
|---|---|
| **Volume** | 大量（数据规模大） |
| **Velocity** | 高速（产生和处理速度快） |
| **Variety** | 多样（结构化、半结构化、非结构化） |
| **Value** | 低价值密度（价值密度低但总价值高） |
| **Veracity** | 真实性（数据质量） |

> 前 4 个（4V）是基础，第 5 个 Veracity 是补充。**注意 Value 是"价值密度低"**，这是最容易错的点。

**大数据处理流程**
```
数据采集 → 数据预处理 → 数据存储 → 数据分析 → 数据展现
```

### 2.4 5G 的三大应用场景（必考）

| 场景 | 全称 | 特点 | 应用 |
|---|---|---|---|
| **eMBB** | 增强移动宽带 | **高速率** | 高清视频、VR/AR |
| **mMTC** | 海量机器类通信 | **大连接** | 物联网、智慧城市 |
| **uRLLC** | 超可靠低时延通信 | **低时延高可靠** | 自动驾驶、工业控制、远程手术 |

> 记忆：**eMBB 快、mMTC 多、uRLLC 稳。**

**5G 的关键性能指标**
- 峰值速率：20 Gbps
- 用户体验速率：100 Mbps
- 时延：1 ms
- 连接密度：100 万设备/km²

### 2.5 其他新技术

| 技术 | 核心特征 |
|---|---|
| **人工智能（AI）** | 机器学习、深度学习、自然语言处理、计算机视觉 |
| **区块链** | 分布式账本、去中心化、不可篡改、智能合约 |
| **边缘计算** | 数据在**靠近源头**处理，降低时延、减少带宽 |
| **数字孪生** | 物理实体的**虚拟映射**，实时同步 |
| **VR/AR/MR** | 虚拟现实/增强现实/混合现实 |

**数字孪生的三要素**：物理实体、虚拟模型、数据连接

## 四、第3章 信息系统治理

### 3.1 IT 治理

**定义**：IT 治理是**董事会和高层管理者**的职责，通过**领导、组织架构和流程**，确保 IT 与业务目标一致、风险可控、价值实现。

**IT 治理的核心目标（三个）**
```
① 与业务目标一致（战略对齐）
② 有效利用信息与 IT（价值交付）
③ 风险管理（风险控制）
```

**IT 治理与 IT 管理的区别（必考）**

| | IT 治理 | IT 管理 |
|---|---|---|
| 层级 | **高层（董事会）** | 执行层（IT 部门） |
| 关注 | **做什么、该不该做** | **怎么做、做得好不好** |
| 内容 | 决策权、问责、监督 | 计划、执行、运维 |

### 3.2 常见的 IT 治理框架

| 框架 | 侧重点 |
|---|---|
| **COBIT** | IT 治理与控制，**最主流的 IT 治理框架** |
| **ITIL** | IT 服务管理（服务生命周期） |
| **ISO/IEC 38500** | IT 治理国际标准（原则：责任、战略、收购、性能、符合、人类行为） |

**COBIT 的核心**
- 五个原则：满足干系人需求、覆盖企业端到端、应用单一整合框架、实现整体方法、区分治理与管理
- 治理域：**EDM**（评价、指导、监控）

### 3.3 IT 审计

**定义**：对 IT 相关的**控制、风险、合规**进行独立评估。

**三种类型**
- **合规性审计**：是否遵守法规/标准
- **财务审计**：IT 相关财务的真实性
- **绩效审计**：IT 投入的效益

## 五、第4章 信息系统管理

### 4.1 信息系统运维管理

**运维的内容**
```
① 基础设施运维（机房、网络、服务器）
② 应用系统运维（部署、监控、优化）
③ 数据运维（备份、恢复、安全）
④ 安全运维（防护、监控、应急）
⑤ 服务管理（工单、变更、发布）
```

**运维的四个转变**
```
从"被动响应" → "主动预防"
从"人工操作" → "自动化"
从"技术导向" → "服务导向"
从"成本中心" → "价值中心"
```

### 4.2 IT 服务管理（ITSM）

**ITIL 的核心流程（重点）**

| 流程 | 内容 |
|---|---|
| **事件管理**（Incident） | 尽快**恢复服务**（不找根因） |
| **问题管理**（Problem） | 找**根本原因**，防止重复发生 |
| **变更管理**（Change） | 控制变更风险 |
| **配置管理**（Configuration） | 配置项与 CMDB |
| **发布管理**（Release） | 发布到生产环境 |
| **服务台**（Service Desk） | 单一联系点（SPOC） |

> **注意区分**：**事件管理**追求"快速恢复"，**问题管理**追求"根因消除"。这是 ITIL 最常考的点。

**服务级别协议（SLA）**
- 定义服务提供方与客户之间的**服务标准与责任**
- 关键指标：可用性（如 99.9%）、响应时间、解决时间
- **OLA**（运营级别协议）：内部团队之间的协议
- **UC**（支持合同）：与外部供应商的合同

### 4.3 信息系统安全管理

**信息安全的三个基本属性（CIA，必背）**

| 属性 | 含义 |
|---|---|
| **机密性**（Confidentiality） | 不被未授权者获取 |
| **完整性**（Integrity） | 不被未授权篡改 |
| **可用性**（Availability） | 授权者可正常使用 |

> 扩展还有：**可控性、不可否认性**（五要素）。

**信息安全等级保护（等保）**
- 五个等级，一级最低、五级最高（涉及国家安全）
- 常见企业系统需过**等保三级**

**常见安全威胁**
- 恶意代码（病毒、蠕虫、木马）
- 网络攻击（DDoS、SQL 注入、XSS、APT）
- 社会工程（钓鱼、欺骗）
- 内部威胁

**安全防护措施**
```
物理安全、网络安全、主机安全、应用安全、数据安全、管理安全
```

## 六、第5章 信息系统工程

### 5.1 软件工程生命周期

**经典模型（必考辨析）**

| 模型 | 特点 | 适用 |
|---|---|---|
| **瀑布模型** | 顺序推进、阶段严格、文档驱动 | 需求**明确稳定** |
| **原型模型** | 快速构建原型，澄清需求 | 需求**不明确** |
| **螺旋模型** | 迭代 + **风险分析**（每个螺旋含风险分析） | **大型高风险**项目 |
| **V 模型** | 开发与测试**对应**（需求↔验收测试） | 强调测试 |
| **增量模型** | 分批交付功能 | 可分模块交付 |
| **敏捷模型** | 迭代、拥抱变化 | 需求多变 |

> **螺旋模型最独特的地方：每个迭代都包含风险分析**，这是它区别于其他模型的核心。

**V 模型的对应关系（易考）**
```
需求分析 ←→ 验收测试
概要设计 ←→ 系统测试
详细设计 ←→ 集成测试
编码     ←→ 单元测试
```

### 5.2 软件测试

**测试的四个层级**
```
单元测试 → 集成测试 → 系统测试 → 验收测试
```

**测试类型**

| 类型 | 说明 |
|---|---|
| **黑盒测试** | 不看内部结构，只测输入输出（功能测试） |
| **白盒测试** | 看内部逻辑（路径覆盖、语句覆盖） |
| **灰盒测试** | 介于两者之间 |
| **回归测试** | 修改后确认没破坏原有功能 |
| **性能测试** | 负载、压力、并发 |

**测试的三大阶段（按目的）**
- **α 测试**：开发环境内，开发者参与
- **β 测试**：真实用户环境，用户参与
- **验收测试**：客户正式验收

### 5.3 软件维护的四种类型（必考）

| 类型 | 目的 | 占比 |
|---|---|---|
| **改正性维护** | 修复发现的**缺陷/错误** | 约 20% |
| **适应性维护** | 适应**环境变化**（新 OS、新硬件） | 约 25% |
| **完善性维护** | **增加功能**、提升性能（占比最大） | **约 50%** |
| **预防性维护** | 提高**可维护性**，预防未来问题 | 约 5% |

> 记忆：**完善性维护占比最大（约 50%）**，这是最高频考点。

### 5.4 软件复用与构件

- **软件复用**：复用已有软件资产（代码、设计、文档、架构）
- **构件（Component）**：可独立部署、可组合的软件单元
- 复用层次：**代码复用 < 设计复用 < 架构复用 < 领域复用**

### 5.5 统一过程（RUP）

**RUP 的四个阶段**
```
初始（Inception）→ 细化（Elaboration）→ 构建（Construction）→ 移交（Transition）
```

**RUP 的三大特点**
- **用例驱动**（Use-Case Driven）
- **以架构为中心**（Architecture-Centric）
- **迭代与增量**（Iterative and Incremental）

> 每个阶段结束都有**里程碑**：生命周期目标、生命周期架构、初始操作能力、产品发布。

### 5.6 净室软件工程、逆向工程

- **逆向工程**：从代码反推设计/需求
- **再工程（Reengineering）**：逆向工程 + 重构 + 正向工程

## 七、高频易错对照表

| # | 陷阱 | 正解 |
|---|---|---|
| 1 | 大数据 5V 中 Value 是价值高 | Value 是**价值密度低**（但总价值高） |
| 2 | 云计算 IaaS 提供软件 | IaaS 提供**基础设施**；SaaS 才是软件 |
| 3 | 物联网三层是"设备-网络-云" | 是**感知层-网络层-应用层** |
| 4 | 5G 的 uRLLC 是大连接 | uRLLC 是**低时延高可靠**；mMTC 才是大连接 |
| 5 | 事件管理要找根本原因 | 事件管理**快速恢复**；问题管理才找根因 |
| 6 | 完善性维护占比最小 | 完善性维护占比**最大（约 50%）** |
| 7 | 螺旋模型没有风险分析 | 螺旋模型的**核心特征就是风险分析** |
| 8 | 信息的 Value 属性是价值 | 信息质量属性中是**经济性**；Value 属大数据 |
| 9 | IT 治理 = IT 管理 | 治理在**高层**（方向），管理在**执行层** |
| 10 | 国家信息化六要素中资源是龙头 | **应用是龙头**，资源是核心 |
| 11 | V 模型中需求对应单元测试 | 需求 <-> **验收测试**；编码 <-> 单元测试 |
| 12 | 白盒测试不看代码 | **白盒看代码逻辑**；黑盒才不看 |
| 13 | 区块链是中心化的 | 区块链是**去中心化**分布式账本 |
| 14 | 等保五级最低 | **一级最低，五级最高** |
| 15 | 数字孪生只有虚拟模型 | 三要素：**物理实体 + 虚拟模型 + 数据连接** |

1. 精确性、完整性、可靠性、及时性、经济性、可验证性、安全性。
2. 信息技术应用（龙头）、信息资源（核心）、信息网络（基础）、信息技术和产业（支撑）、信息化人才（关键）、政策法规标准（保障）。
3. 信息基础设施、融合基础设施、创新基础设施。
4. 感知层、网络层、应用层。
5. IaaS（基础设施）、PaaS（平台）、SaaS（软件）。
6. Volume（大量）、Velocity（高速）、Variety（多样）、Value（价值密度低）、Veracity（真实性）。Value 指价值密度低但总价值高。
7. eMBB（高速率）、mMTC（大连接）、uRLLC（低时延高可靠）。
8. IT 治理在高层（董事会），关注方向与问责；IT 管理在执行层，关注执行与效率。
9. 机密性（Confidentiality）、完整性（Integrity）、可用性（Availability）。
10. 事件管理追求快速恢复服务；问题管理追查根本原因防止复发。
11. 瀑布、原型、螺旋、V 模型、增量、敏捷。螺旋模型的独特之处是**每个迭代都包含风险分析**。
12. 改正性、适应性、完善性（占比最大约 50%）、预防性。
13. 验收测试。
14. 初始、细化、构建、移交；用例驱动、以架构为中心、迭代与增量。
