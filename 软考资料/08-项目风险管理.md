# 项目风险管理 · 重点知识点

> 第4版教材第15章 · 7 个过程 · 综合知识 4~6 分 · **案例与论文极高頻**

---

## 一、定位：风险 = 不确定性对目标的影响

**核心定义**：风险管理是规划、识别、分析、应对和监控项目**风险**的过程。

**风险的双重性（第4版强调）**

| 类型 | 含义 | 应对方向 |
|---|---|---|
| **威胁（Threat）** | 消极风险，**不利**影响 | 规避、转移、减轻、接受 |
| **机会（Opportunity）** | 积极风险，**有利**影响 | 开拓、分享、提高、接受 |

> **关键论断**：风险是**不确定性**，既有威胁也有机会。第4版明确要求同时管理"威胁"与"机会"，这是与第3版的重要区别。

**风险的三个要素**
- **风险事件**（可能发生什么）
- **概率**（发生可能性）
- **影响**（发生后对目标的影响程度）
- **风险值 = 概率 × 影响**

**7 个过程与过程组分布**

```
规划 ─── 规划风险管理、识别风险、实施定性风险分析、实施定量风险分析、规划风险应对
执行 ─── 实施风险应对
监控 ─── 监督风险
```

**风险管理逻辑链**

```
定规则 → 找风险 → 排序（定性）→ 量化（定量）→ 定对策 → 执行 → 监控
```

## 二、七个过程总表

| 过程 | 过程组 | 关键输入 | 关键工具 | 关键输出 |
|---|---|---|---|---|
| **规划风险管理** | 规划 | 项目章程、项目管理计划、项目文件、EEF、OPA | 专家判断、数据分析、会议 | **风险管理计划** |
| **识别风险** | 规划 | 项目管理计划、项目文件、协议、采购文档、EEF、OPA | **头脑风暴、核对单、访谈、根本原因分析、假设条件与制约因素分析、SWOT 分析、文档分析** | **风险登记册**、**风险报告**、项目文件更新 |
| **实施定性风险分析** | 规划 | 项目管理计划、项目文件、EEF、OPA | **风险数据质量评估、风险概率和影响评估、概率和影响矩阵、层级图（气泡图）** | 项目文件更新 |
| **实施定量风险分析** | 规划 | 项目管理计划、项目文件、EEF、OPA | **模拟（蒙特卡洛）、敏感性分析（龙卷风图）、决策树分析、影响图** | 项目文件更新 |
| **规划风险应对** | 规划 | 项目管理计划、项目文件、EEF、OPA | **威胁应对策略、机会应对策略、应急应对策略、整体项目风险应对策略**、数据分析、决策 | **变更请求**、项目管理计划更新、项目文件更新 |
| **实施风险应对** | 执行 | 项目管理计划、项目文件、EEF、OPA | 人际关系与团队技能、PMIS | 变更请求、项目文件更新 |
| **监督风险** | 监控 | 项目管理计划、项目文件、工作绩效数据、工作绩效报告 | **技术绩效分析、储备分析**、审计、会议 | 工作绩效信息、变更请求 |

**三条容易记错的点**
1. **识别风险**是**迭代**过程，全过程反复进行，不是只做一次
2. **定性分析**输出到项目文件（更新风险登记册），**不产生新的独立输出**
3. **规划风险应对**才输出**变更请求**（因为应对措施可能改变基准）

## 三、逐个重点

### 15.2 规划风险管理

**风险管理计划内容**
- 风险管理策略与方法
- 角色与职责
- **风险类别（RBS 风险分解结构）**
- **风险概率与影响的定义**（如"高=70%以上"）
- **概率影响矩阵**
- 风险临界值（风险敞口）
- 报告格式、跟踪机制
- 储备与应急策略

**风险分解结构（RBS）**：按风险**来源**分类（技术、管理、商业、外部），注意与资源分解结构同名但不同义。

---

### 15.3 识别风险

**核心**：识别**单个项目风险**和**整体项目风险**的来源，并记录其特征。

**关键工具辨析**

| 工具 | 用途 |
|---|---|
| **头脑风暴** | 集思广益，快速生成大量风险 |
| **核对单（Checklist）** | 基于历史经验，防止遗漏 |
| **假设条件分析** | 检验假设是否成立（假设不成立就是风险） |
| **SWOT 分析** | **优势、劣势、机会、威胁**——同时识别威胁与机会 |
| **根本原因分析** | 找风险背后的深层原因 |
| **文档分析** | 从合同、计划中发现不一致与隐含风险 |
| **访谈** | 向专家/资深人员了解经验风险 |

**风险登记册的内容（必背）**
① 风险**编号/标识**
② 风险**描述**（原因 → 事件 → 影响）
③ 风险**责任人**（owner，必须有具体的人）
④ 风险**类别**
⑤ 概率与影响评估
⑥ 优先级/风险值
⑦ **应对策略与措施**
⑧ 应急储备
⑨ 触发条件
⑩ 状态（活跃/已关闭）

> 关键：**每个风险必须有明确的责任人（owner），不能只写"项目团队"。**

---

### 15.4 实施定性风险分析

**核心**：对风险**排序**，确定优先级（**不需要精确数值**）。

| 工具 | 说明 |
|---|---|
| **风险概率和影响评估** | 评估每项风险的概率与影响等级（高/中/低） |
| **概率和影响矩阵** | 把概率与影响交叉，划分高/中/低风险区（**红黄绿区**） |
| **风险数据质量评估** | 检查风险数据的准确性、完整性、可靠性 |
| **层级图（气泡图）** | 用气泡大小表示第三个维度（如紧迫性） |

**概率影响矩阵示例**

```
        影响：很低  低   中   高  很高
概率
很高           中   高   高   极高 极高
高             中   中   高   高   极高
中             低   中   中   高   高
低             低   低   中   中   高
很低           低   低   低   中   中
```

> 落在**高风险区（红区）**的风险需要优先制定应对措施。

---

### 15.5 实施定量风险分析

**核心**：对**高优先级风险**做**数值化**分析，量化整体风险敞口。

| 工具 | 说明 | 输出 |
|---|---|---|
| **模拟（蒙特卡洛）** | 反复随机抽样，得到完工时间/成本的**概率分布** | "80% 概率在 120 天内完工" |
| **敏感性分析（龙卷风图）** | 找对结果影响**最大**的变量 | 龙卷风图（条形越长影响越大） |
| **决策树分析** | 计算各方案的**EMV** | 选 EMV 最优的方案 |
| **影响图** | 展示变量之间的因果关系 | 识别关键影响路径 |

**决策树与 EMV（案例分析高频计算）**

```
EMV（期望货币值）= Σ (每个分支的概率 × 该分支的金额)

例：某方案成功概率 60%，成功收益 100 万；失败概率 40%，失败损失 30 万
EMV = 0.6 × 100 + 0.4 × (−30) = 60 − 12 = 48 万
```

**决策树标准作答步骤**
```
① 画出决策节点（方框）与机会节点（圆圈）
② 标注每个分支的概率与金额
③ 从右向左计算每个机会节点的 EMV
   EMV = Σ(概率 × 金额)
④ 在决策节点选择 EMV 最大的方案
⑤ 结论：推荐方案 X，期望收益 ___ 万元
```

> 注意：**损失要记为负数**，这是最容易算错的地方。

### 15.6 规划风险应对（案例与论文核心）

**威胁（消极风险）的五种应对策略（必背）**

| 策略 | 做法 | 举例 | 风险敞口 |
|---|---|---|---|
| **规避（Avoid）** | **改变计划**，彻底消除风险 | 改用成熟技术、缩小范围 | **降为 0** |
| **转移（Transfer）** | 把风险**后果**转移给第三方 | 买保险、外包、固定总价合同 | 降低（付出成本） |
| **减轻（Mitigate）** | **降低概率或影响** | 增加测试、冗余设计、原型验证 | 降低 |
| **接受（Accept）** | 不主动应对，**准备应急储备** | 建立应急储备、应急计划 | 不变 |
| **上报（Escalate）** | 超出 PM 权限，**上报高层/发起人** | 影响公司战略的风险 | 由上层处理 |

> 第4版新增**"上报"**策略，这是与第3版的重要区别。
> **接受**分两种：**主动接受**（建立应急储备）、**被动接受**（什么都不做，只记录）。

**机会（积极风险）的五种应对策略（必背）**

| 策略 | 做法 | 举例 |
|---|---|---|
| **开拓（Exploit）** | 确保机会**一定实现** | 派最优秀的资源、采用新技术 |
| **分享（Share）** | 与第三方**合作共享**机会 | 联合体投标、合作伙伴 |
| **提高（Enhance）** | **增加概率或影响** | 增加资源投入、提前启动 |
| **接受（Accept）** | 愿意利用但不主动追求 | 记录备查 |
| **上报（Escalate）** | 超出权限，上报 | — |

**记忆对应关系（必背）**
```
威胁：规避 ↔ 机会：开拓      （都最彻底，一个消除一个确保）
威胁：转移 ↔ 机会：分享      （都涉及第三方）
威胁：减轻 ↔ 机会：提高      （都调节概率/影响）
威胁：接受 ↔ 机会：接受      （都一样）
威胁：上报 ↔ 机会：上报      （都一样）
```

**应急应对策略**
- 为**特定风险**制定应急计划（contingency plan），并设定**触发条件**
- 只有触发条件满足时才执行

**整体项目风险应对策略**
- **规避、开拓、转移/分享、减轻/提高、接受**

**储备分析**
- **应急储备**：应对**已识别**风险（已知-未知），在基准内，PM 管理
- **管理储备**：应对**未识别**风险（未知-未知），不在基准内，高层管理

---

### 15.7 实施风险应对

**核心**：**执行**已商定的风险应对计划。

- 由**风险责任人**负责执行
- PM 负责确保措施被执行，并评估执行效果
- 常见的失败：**应对计划制定了但没人执行**

---

### 15.8 监督风险

**核心**：监控风险状态、识别新风险、评估应对效果。

| 工具 | 说明 |
|---|---|
| **技术绩效分析** | 比较技术成果与计划，早期发现偏差 |
| **储备分析** | 监控剩余储备是否充足，判断风险暴露程度 |
| **风险审计** | 检查风险应对措施的有效性 |
| **会议** | 定期的风险评审会 |

**储备分析的关键判断**
- 剩余应急储备 < 剩余风险敞口 → 需要追加储备或采取更多措施

## 四、高频易错对照表

| # | 陷阱 | 正解 |
|---|---|---|
| 1 | 风险只指坏事 | 风险包括**威胁和机会**（第4版强调） |
| 2 | 识别风险只在初期做一次 | **迭代进行**，全过程反复识别 |
| 3 | 定性分析用数值精确计算 | 定性只做**排序**；定量才数值化 |
| 4 | 定性和定量都要对全部风险做 | 定量只针对**高优先级风险** |
| 5 | 规避和减轻是一回事 | 规避**消除**风险（敞口→0）；减轻只**降低**概率/影响 |
| 6 | 转移后就没责任了 | 转移的是**财务后果**，责任仍可能保留（如质量责任） |
| 7 | 接受就是不管 | **主动接受**要建立应急储备与应急计划 |
| 8 | 第4版没有"上报"策略 | 第4版**新增上报**，用于超出 PM 权限的风险 |
| 9 | 风险责任人可以是"项目团队" | 必须是**具体的人（owner）** |
| 10 | 决策树求 EMV 时损失记正数 | 损失必须记为**负数** |
| 11 | 敏感性分析用蒙特卡洛 | 敏感性用**龙卷风图**；蒙特卡洛是**模拟** |
| 12 | 应急储备应对未识别风险 | 应急储备应对**已识别**；管理储备应对**未识别** |
| 13 | 风险登记册属 OPA | 属**项目文件** |
| 14 | 风险报告与风险登记册是同一个 | 风险登记册记**单个风险**；风险报告汇总**整体风险敞口** |
| 15 | 概率影响矩阵属定量工具 | 属**定性**分析工具 |

## 五、案例题万能模板

```
问题：
1. 未制定风险管理计划，无风险管理流程
2. 风险识别不全面，未识别关键风险（尤其技术/外部风险）
3. 只识别威胁，忽略机会（第4版要求双向）
4. 未做定性与定量分析，风险无优先级
5. 风险未指定责任人（owner），无人跟踪
6. 已识别的风险未制定应对措施，或措施未执行
7. 未设置应急储备，风险发生后无资金/时间应对
8. 风险监控缺失，未定期评审风险状态

措施：
1. 编制风险管理计划，明确流程、角色、概率影响矩阵与临界值
2. 采用头脑风暴、核对单、SWOT、假设分析、文档分析全面识别风险
3. 同时识别威胁与机会，为机会制定开拓/分享/提高策略
4. 用概率影响矩阵做定性排序，对高优先级风险做定量分析（EMV/蒙特卡洛）
5. 为每项风险指定具体责任人并明确职责
6. 按风险类型选择策略（规避/转移/减轻/接受/上报），制定应急计划与触发条件
7. 合理设置应急储备（已识别风险）与管理储备（未识别风险），并定期做储备分析
8. 定期召开风险评审会，审计应对措施有效性，动态更新风险登记册
```

## 六、论文要点（论风险管理 / 论采购与风险）

**结构**：背景 300 字 → 过程论述 1500 字 → 问题与解决 400 字 → 总结 200 字

**必须体现的加分项**
- **一次真实的风险化解**：识别到"核心第三方接口延期"风险 → 概率 60%、影响大 → 采取**减轻**（提前联调 + 备用方案）→ 最终影响控制在 5 天内
- **定量分析的具体数据**：蒙特卡洛算出 80% 概率在 150 天内完工，据此向高层申请 15 天缓冲
- **机会管理的实例**（第4版加分点）：识别到"可复用另一项目的组件"这个**机会** → 采用**提高**策略（投入 2 人适配）→ 节省 30 天
- **应急储备的使用**：动用了 2 次应急储备（共 8 万），均对应已登记风险
- **风险责任人的落地**：23 项风险各有明确 owner，每周评审状态
